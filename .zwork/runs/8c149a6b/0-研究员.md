## (e) Suspected mobile issues, with evidence

1. **Testimonial grid never collapses on phones (highest-impact finding).** `repeat(3, minmax(0, 1fr))` at styles.css:2569–2572 with no override in any of the 20 media blocks (inventory in (a)). On a 375–420px viewport each card is ~100–120px wide; uppercase figcaptions with `letter-spacing: 0.08em` (2602–2605) and 18px-minimum blockquotes (2594) will wrap heavily. Note `minmax(0, 1fr)` (2569–2572) plus card `overflow: hidden` (2544) means this presents as cramped/truncated content, not page-level horizontal scroll.
2. **Mobile footer CSS styles elements absent from static HTML.** Rules at 3154–3180 target `.footer-signature` / `.footer-owner` / `.footer-meta`, which exist only after JS injection (site.js:776–819). With JS unavailable the ≤700px footer renders only wordmark + tagline + stacked links (rules 3129–3153 still apply). Diagnosis-relevant: signature/owner/meta issues are not reproducible from HTML alone.
3. **Signature sizing is contained by clipping, not by fitting.** Base `clamp(56px, 13vw, 190px)` (786), mobile `clamp(44px, 12.6vw, 84px)` (3158). Arithmetic: at 375px, 12.6vw ≈ 47px → "Neef Studios" ≈ 280px, fits; at 701–800px (tablet band) 13vw ≈ 91–104px → text ≈ 546–624px vs ~613–700px available — fits, but tight. Any excess is clipped by `.site-footer { overflow: hidden }` (1679) and `html, body { overflow-x: clip }` (3318, 3322) — so page scrollbars are prevented, but edge-truncation of the signature is visually possible rather than structurally impossible.
4. **`.wordmark { white-space: nowrap }` (138)** — low risk: the footer wordmark contains only an SVG (`brand-mark`, height 30px base / 25px at ≤420px, 3197–3200) with `img { max-width: 100% }` (102–104, 3326–3330); no text to overflow. The ≤420px `.wordmark { font-size: 12px }` (3193–3196) affects only the anchor's font metrics.
5. **`.footer-owner`/`.footer-meta` fixed at 10px** (3171–3176, 3178–3180). Factual: the founder line "OLUWANIFEMI FAYEFUNMI · FOUNDER & CEO" at 10px uppercase + 0.12em tracking is ~300px wide → single line at 375px+, wraps to two lines at 320px viewports (content width ≈ 275px after 7% padding, 3188–3192).
6. **Reveal animations can render the sections invisible until observed.** `.testimonial-grid.reveal-group` children start `opacity: 0` (2882–2890) and the quote band's blockquote starts fully clipped (2921–2924); both only become visible when site.js adds `.is-inview` (1082–1097). The `html:not(.js)` fallback (2713–2717) covers no-JS, but a JS-loaded-observer-never-fires scenario leaves mobile users with an apparently empty section.
7. **Duplicated selectors** `.testimonial .body-copy` (1602, 1619) and `.testimonial .text-link` (1606, 1625) — additive today, but a maintenance trap: editing one copy silently leaves the other applying.

**Not found / ruled out:** no 640px/480px breakpoints; no testimonial overrides at any width; no single-column testimonial rule; no fixed pixel widths or `nowrap` on footer text elements; no conflicting (same-property) duplicate definitions for `.testimonial-*`.

**Suggested next step (if you proceed to diagnosis):** the single mobile-viewport repro worth doing first is index.html at 360–420px on the `.testimonial-grid` section — that is the only place where mobile behavior visibly diverges from the intended stacked layout used for every other grid on the site (e.g., `.projects`, `.journal-grid`, `.packages-grid` all get `grid-template-columns: 1fr` at 2685–2690 and 3036–3046 while `.testimonial-grid` was left out).
